# MAVRO website

The public MAVRO website. Currently one page: the homepage. Vite 5, React 18, TypeScript, npm.

```bash
npm install
npm run dev        # http://localhost:5180
npm run shots      # re-capture the product screenshots (needs the dev server running)
npm run build      # type-check, bundle, prerender to static HTML in dist/
npm run preview    # serve dist/ on http://localhost:5181
```

## The product screenshots

The screens on the site are real screenshots of a prototype of the MAVRO interface, built for this purpose in
[prototype/](prototype/): eight static HTML screens sharing one stylesheet (`app.css`) and one script
(`shell.js`, which draws the sidebar, top bar and charts).

| Screen | File | Used in |
|---|---|---|
| Operations overview | `overview.html` | Hero, Views |
| Sales order SO-24817 | `sales-order.html` | Hero, One system, Order to cash, Views |
| Shop floor | `production.html` | Hero, Order to cash, Production, Views |
| Sourcing, RFQ-0311 | `procurement.html` | Procure to pay |
| Inspection lot L-0932 | `quality.html` | Order to cash, Production |
| Inventory | `inventory.html` | Order to cash, Views |
| Receivables and cash | `finance.html` | Order to cash, Views |
| Roles and audit | `access.html` | Control |

`npm run shots` renders each at 1440 × 960 (2x) in headless Edge or Chrome and writes WebP files to
`src/assets/screens/` at two widths. To change a screen, edit its HTML and run `npm run shots <name>`.

All data in them is invented (Northfield Precision, Kestrel Pumps, SO-24817 and so on) and is kept consistent
with the story told in the page copy ([src/data/story.ts](src/data/story.ts)). The footer says the screens use
sample data. The prototype is a design reference, not the shipping application.

## Design system

Tokens live in [src/styles/tokens.css](src/styles/tokens.css) and nowhere else.

- **Light.** White pages and a pale grey (`--mist`) for alternate sections. Near-black type.
- **One accent: MAVRO blue** (`#2b4eff`), shared with the product UI so the screenshots feel native to the page.
  It marks the flow (the line that links one business event to the next) and nothing decorative.
- **Type.** Instrument Sans for the site; Inter inside the product screens. No eyebrow labels: sections open
  directly on their headline.
- **Screenshots** sit on the page with one soft, wide shadow (`--shadow-screen`) and no browser chrome.

## Motion

No animation library. Three primitives, all in [src/motion](src/motion):

| Primitive | What it does |
|---|---|
| `useScrollProgress` / `useScrollSteps` | One shared rAF loop writes each scene's scroll progress to `--p`; CSS turns it into transforms and opacity |
| `data-reveal` | Content enters once when it reaches the viewport |
| `data-live` | Looping animation runs only while its region is on screen |

Only `transform` and `opacity` are animated. The two pinned scenes (One system, Order to cash) have a static
presentation, used on small screens, short windows and with `prefers-reduced-motion`.

## Structure

```
prototype/             the product screens that get screenshotted
src/
  App.tsx              the page, in story order
  assets/screens/      captured screenshots (generated by npm run shots)
  data/                site facts and the sample business story
  motion/              scroll loop and hooks
  components/          Nav, Footer, Logo, FlowRail, Screen
  sections/            Hero, OneSystem, OrderToCash, ProcureToPay, Production, Views,
                       Industries, Control, FinalCta (each with its own stylesheet)
  seo/head.ts          title, meta, Open Graph, JSON-LD
  entry-client.tsx     hydrates the prerendered page
  entry-server.tsx     renders it to HTML at build time
scripts/
  shots.mjs            captures the prototype
  prerender.mjs        injects the HTML and head, preloads the display font, writes robots.txt and sitemap.xml
```
